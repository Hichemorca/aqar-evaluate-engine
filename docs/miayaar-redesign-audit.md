# MIAYAAR Product Redesign Audit

## Scope

This audit covers the five current HTML surfaces: the valuation form, Accuracy Dashboard, Market Intelligence, Calibration Console, and Export. The redesign is limited to the presentation layer on branch `design/miayaar-product-redesign`. Valuation calculations, calibration rules, API contracts, data artifacts, GIS scoring, and observation boundaries remain out of scope.

## Current architecture

MIAYAAR is a static HTML/CSS/Vanilla JavaScript application deployed on Netlify. The runtime is split into page entry files and shared modules under `shared/`. Accuracy and calibration rendering include JavaScript-generated markup, so their CSS must remain compatible with existing IDs, classes, `data-action` hooks, and dynamic states.

## Current strengths to preserve

The platform already has CSP hardening, semantic skip links, keyboard-accessible autocomplete behavior, protected API boundaries, responsive table containers, explicit DLD evidence states, manual GIS loading, and regression tests covering the valuation and calibration contracts. The current dark navy and emerald identity is also a suitable foundation for an institutional analytics product.

## Main presentation gaps

The five pages use duplicated page-level tokens and card rules. Navigation is inconsistent and mostly footer-based. Public pages lack a shared AppShell/PageHeader pattern. The valuation result is generated by `shared/index-result-rendering-runtime.js` and therefore needs a presentation-only refactor with stable result IDs and action hooks. Accuracy and Market Intelligence use dense dashboards without a unified hierarchy for primary metrics, evidence, and secondary metadata. Calibration has a useful grouped field-card structure but lacks a consistent shell and clearer status hierarchy. Export is visually minimal and does not yet look like an institutional report surface.

## Design direction

The branch will introduce centralized MIAYAAR tokens for color, typography, spacing, radius, shadow, focus, and motion. The visual language will remain deep navy, off-white, muted slate, and restrained emerald accents. Amber remains a semantic warning or confidence state rather than the primary brand accent. The layout will use a shared full-bleed masthead, a constrained content frame, clear page headers, surface hierarchy, and responsive mobile-first stacking.

## Implementation boundaries

The first implementation slice will centralize tokens and shared shell primitives, then apply them to existing page-local styles without changing runtime behavior. Later slices may improve page-specific hierarchy and result rendering, but must preserve existing IDs, API calls, data attributes, calculation modules, and test contracts. New future navigation items will be presented only as clearly labeled placeholders if added.

## Acceptance criteria

The redesign is acceptable only if all existing tests pass, no inline JavaScript or CSS is introduced, no protected data or secret is changed, all current page routes remain available, keyboard focus remains visible, tables remain usable on narrow screens, and the public valuation result remains functionally identical.
