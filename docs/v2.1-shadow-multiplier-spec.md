# v2.1 Shadow Direct-Multiplier Specification

## Purpose

v2.1 introduces direct multipliers controlled by calibration, but the first implementation is **shadow-only**. The current official valuation, official Accuracy, historical results, active fallback policy, and existing method weights remain unchanged.

## General rule

The neutral multiplier is `1.00`. Empty fields, Unknown values, unverified free text, insufficient project evidence, and inapplicable property types contribute `1.00`.

For a shadow result:

> `Shadow Value = Baseline Value × Project Multiplier × BUA/Plot Multiplier × Renovation Multiplier`

The combined product is clamped by configured lower and upper bounds. The default shadow configuration is disabled until a separately reviewed configuration is activated for the experiment.

## Project / Building

Project matching uses the exact normalized combination of `propertyType`, selected DLD `district`, and a DLD-derived `masterProject` or `project` suggestion. A manually typed name is not verified and contributes `1.00`. A selected DLD suggestion must meet the configured minimum evidence threshold, currently five transactions, before a configured project multiplier can apply.

Project candidates are generated from actual eligible DLD sales by comparing the project's median price per square metre with the median of other transactions in the same property type and district. Candidate values are shrunk toward `1.00` and bounded conservatively. These candidates are diagnostic; they are not automatically written into calibration.

## BUA and Plot Area

For Villa and Townhouse only, the ratio is:

> `BUA/Plot Ratio = BUA ÷ Plot Area`

The calibration contains ordered ratio bands. The first band whose `maxRatio` is greater than or equal to the observed ratio supplies the direct multiplier. A positive BUA and Plot Area are both required. Apartment does not expose BUA in v2.1, and Land does not receive this ratio multiplier because it has no BUA field.

The current DLD files do not contain verified separate BUA and Plot Area values, so no DLD-derived BUA/Plot coefficient is claimed yet. User-entered values can be tested as a scenario input, but they require holdout evidence before official use.

## Last Renovation Year

For Apartment, Villa, and Townhouse, the renovation age is:

> `Renovation Age = Current Year − Last Renovation Year`

The configured renovation-age bands supply the direct multiplier. The field is valid only when it is an integer at least the construction year and no later than the current year. The UI shows it only when the property is more than five years old.

## Governance

The calibration console will expose the shadow settings separately from official method weights. Every saved version retains the normal calibration identity and the v2.1 shadow configuration. Enabling the shadow configuration does not change the official evaluator; it only permits isolated comparison and explanation until an explicit owner approval is recorded for any production change.

## Required evidence before production activation

A reviewed experiment must report MAE, bias, P90 absolute error, ±15% hit rate, coverage, and fallback transitions by property type. It must use time-separated training and holdout data, exclude invalid or high-dispersion cohorts, preserve a neutral band, and document all active multipliers. No synthetic BUA, Plot Area, or renovation values may be used.
