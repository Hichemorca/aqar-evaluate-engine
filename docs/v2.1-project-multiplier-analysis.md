# v2.1 Project Direct-Multiplier Analysis

**Status:** shadow analysis only. No production evaluator, official Accuracy artifact, calibration configuration, weights, fallback policy, raw DLD source, or historical result was changed.

## Method

The analysis uses only eligible DLD transactions. For each project cohort, it calculates median price per square metre from `actualSalePrice / area` (with `procedureArea` as a fallback), then compares that median with the median of other transactions in the same DLD district and property type. The project cohort must contain at least five transactions.

To avoid allowing small samples to create extreme coefficients, the illustrative candidate multiplier is shrunk toward the neutral value:

> `candidateMultiplier = clamp(1 + (projectMedian / districtMedianExcludingProject − 1) × n/(n+20), 0.95, 1.05)`

This is a **candidate-generation rule**, not an approved calibration rule. A high-dispersion flag is raised when the project cohort's `P75 / P25` price ratio exceeds `2`.

The strongest stable-looking premium examples in this run were `The One at Jumeirah Village Triangle` in Jumeirah Village Triangle for Apartments, with 21 transactions and a project-to-district median index of `2.6985`, and `Arabian Ranches lll - Bliss 2` in Wadi Al Safa 5 for Villas, with 14 transactions and an index of `1.5485`. Both were capped at the conservative candidate multiplier `1.05`.

The strongest discount examples were `WEST AVENUE` in Dubai Marina for Apartments, with 7 transactions and a candidate `0.95`, and `SEASONS COMMUNITY- SUMMER` in Jumeirah Village Circle for Villas, with 6 transactions and a candidate `0.95`. The West Avenue cohort has a very high dispersion ratio of `27.7065`, so it should be treated as a diagnostic warning rather than a trustworthy coefficient.

The Townhouse sample has only three eligible DLD records in one project and therefore does not meet the five-transaction threshold. It remains neutral by evidence policy until more verified transactions exist.

## Temporal holdout shadow test

The holdout cutoff was `2026-07-09`. Candidate project multipliers were trained using only pre-cutoff DLD transactions and applied to post-cutoff verified Accuracy records. The baseline prediction was the existing `aqarValuation`; the shadow prediction was that same value multiplied by the candidate project multiplier when a qualifying project cohort was available. Records without a qualifying cohort retained the baseline unchanged.

The aggregate shadow result is worse than baseline in this first conservative test: MAE increased from `12.128%` to `13.002%`, P90 absolute error increased from `25.767%` to `27.780%`, and the ±15% hit rate declined from `72.112%` to `69.224%`. Villas improved slightly on the ±15% rate, but MAE, bias, and P90 did not improve. Apartments declined on every reported metric.

## Decision

The evidence supports the **direction** of the requested model: project-level differences can be measured from DLD and represented as direct multipliers. However, this particular candidate rule must not be activated. The first holdout test does not demonstrate improvement over the current baseline, and the project-vs-district index remains vulnerable to price mix, date, size, unit quality, and off-plan composition confounding.

The next iteration should test a more robust project estimator before any activation discussion. Suitable safeguards include time normalization, minimum sample and dispersion requirements, a project-versus-district comparison on matched size/room bands where available, and an explicit neutral band. The BUA/Plot Area multiplier remains conceptually defined as a function of `BUA / Plot Area`, but it cannot yet be calibrated from the current DLD files because those fields are absent. Last Renovation Year likewise requires user input and cannot be validated against the current DLD Accuracy outcomes.

## Reproducibility

The runner is `scripts/analyze-v21-project-multipliers.js`; its machine-readable output is `docs/v2.1-project-multiplier-analysis.json`. The runner reads current DLD and Accuracy artifacts and never writes to them.
