## Method

Each origin trains the project estimator only on DLD transactions before `trainEndExclusive` and tests it only on later verified Accuracy records. The estimator uses the same safeguards throughout: at least eight project transactions, at least five peer transactions, time normalization, area/room matching where available, a 5% neutral index band, exclusion of high-dispersion cohorts, shrinkage toward `1.00×`, and bounds of `0.95×` to `1.05×`. Records without a qualifying project cohort retain the official baseline unchanged.

The four windows were selected from the observed data range, which spans January–July 2026. The first window begins testing on 28 April because the verified Accuracy artifact begins on 28 April; subsequent windows use monthly origins through 26 July.

Among 499 project cohorts observed in at least two origins, 62.124% remained within a total multiplier range of `0.01×` or less. This means the sign is often stable, but the exact coefficient is not sufficiently stable for automatic production activation.

The largest ranges reached `0.10×`, including `AYKON CITY 2` for Apartments and `Mudon Al Ranim 3` for Villas. These trajectories moved between the configured bounds, which is a direct warning that the bound can hide underlying instability rather than solve it.

## Interpretation and decision

The rolling-origin result does not support activating the peer-relative project multipliers. The shadow estimator underperforms baseline in every tested origin at the aggregate level, and its coefficient stability is mixed. The most defensible current state is to keep the project multipliers available for shadow analysis, leave them disabled by default, and preserve the current official valuation.

A future experiment should use a separate, pre-declared training/validation/test schedule and should avoid selecting the cap from the same dates used for the final report. It should also consider a more stable hierarchical model that shrinks each project toward a type/district baseline without forcing a multiplier for every project, and it should report uncertainty intervals. No such model is being activated by this validation.
