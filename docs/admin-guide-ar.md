# دليل مدير منصة MIAYAAR

## Calibration Console

**الإصدار:** دليل المدير — 27 أغسطس 2026

**الواجهة:** [MIAYAAR Calibration Console](https://aqar-valuation-engine.netlify.app/admin-calibration)

> **هذا الدليل مخصص للمسؤول الوحيد عن المعايرة.** لوحة المدير تغيّر إعدادات تؤثر في التقييمات الجديدة بعد الحفظ مباشرة. لا تستخدمها للتجارب غير المراجعة، ولا تغيّر أي قيمة إنتاجية قبل اختبارها وتوثيق سبب التغيير.

## 1. وظيفة لوحة المدير

تتيح **Calibration Console** للمسؤول مراجعة وتعديل أوزان طرق التقييم والمعاملات المرتبطة بأنواع العقارات. كل إعداد محفوظ له `configId` خاص به، وتحتفظ التقييمات الجديدة بهوية المعايرة التي استخدمتها. لا تعيد المنصة حساب النتائج التاريخية تلقائيًا عند إنشاء إصدار معايرة جديد.

تعمل اللوحة باللغة الإنجليزية، ولذلك يستخدم هذا الدليل أسماء الأقسام والحقول كما تظهر في الواجهة.

## 2. قواعد الأمان الأساسية

| القاعدة | الإجراء المطلوب |
|---|---|
| سرية Admin token | أدخل token في حقل كلمة المرور فقط، ولا تضعه في README أو Git أو command line أو screenshots أو سجلات المتصفح. |
| حساب واحد | لا تشارك token مع مستخدمين آخرين. عند الشك في تسربه، يجب تدويره من إعدادات Netlify واختبار المصادقة من جديد. |
| لا تغيّر الإنتاج للتجربة | استخدم اختبارًا محليًا معزولًا أو تقريرًا مقارنًا قبل حفظ أي تغيير على الموقع الحي. |
| لا تحفظ قيمًا غير مفهومة | لا تعدّل DCF أو fallback أو معاملات GIS أو Shadow إلا إذا كان سبب التغيير ونطاقه واختباره موثقًا. |
| لا تستخدم بيانات مختلقة | لا تدخل معاملًا مبنيًا على تخمين أو على نتيجة عقار واحد دون دليل كافٍ. |
| الحفظ فوري | زر **Save and activate** ينشئ إصدارًا نشطًا فورًا؛ لا توجد مرحلة Draft أو Preview داخل اللوحة الحالية. |

لا يحتوي هذا الدليل على Admin token ولا يطلبه. يجب أن يبقى token خارج الوثائق والـcommits والرسائل العامة.

## 3. الدخول إلى اللوحة

افتح [Calibration Console](https://aqar-valuation-engine.netlify.app/admin-calibration). أدخل Admin token في حقل **Administrator token**، ثم اضغط **Load configuration**. لا تستخدم قيمة تجريبية أو token قديمًا على الموقع الحي.

عند نجاح المصادقة تظهر رسالة **Configuration loaded. Changes are editable below.** وتتحول الحالة العلوية إلى **Connected** مع `configId` النشط. إذا فشلت المصادقة أو تعذر الاتصال، تظهر الحالة **Not connected** ولا تصبح الإعدادات قابلة للتحرير.

| الحالة | المعنى |
|---|---|
| **Not connected** | لم تتم المصادقة أو فشل الطلب. لا توجد صلاحية لتحرير configuration. |
| **Authenticating…** | يجري التحقق من token. انتظر اكتمال الطلب. |
| **Connected · configId** | تم تحميل الإصدار النشط ويمكن مراجعته وتحريره. |
| **Saving…** | يجري حفظ إصدار جديد؛ لا تغلق الصفحة حتى تظهر النتيجة. |
| **Active · configId** | تم الحفظ والتفعيل بنجاح للإصدارات الجديدة. |

لا تحفظ token في مدير كلمات المرور داخل المشروع أو في ملفات الجهاز المشتركة، ولا ترسله داخل طلب دعم أو issue.

## 4. قراءة الشاشة الرئيسية

بعد التحميل تظهر لوحة **Active calibration** في الجهة الرئيسية، وفي الجهة الجانبية تظهر **Save directly** و**Version history**.

| الجزء | وظيفته |
|---|---|
| **Active calibration** | يعرض `configId` وتاريخ آخر تحديث والإعدادات الحالية. |
| بطاقات أنواع العقارات | بطاقة مستقلة لكل نوع: Apartment، Villa، Townhouse، Office، Retail / Shop، Warehouse، Land. |
| **Save directly** | يعرض عدد القيم التي تغيّرت وحالة صلاحية الأوزان وأزرار الحفظ وإعادة التحميل. |
| **Version history** | يعرض الإصدارات المحفوظة الأخيرة، مع `configId` والتاريخ والمسؤول. |
| **Reload active** | يعيد تحميل الإصدار النشط من الخادم ويهمل التعديلات غير المحفوظة. |

تُفتح بطاقة نوع عقار واحدة في كل مرة. اضغط على اسم النوع لفتحها، واضغط على نوع آخر للانتقال إليه.

## 5. بطاقات أنواع العقارات

تحتوي كل بطاقة على الإعدادات التي تخص ذلك النوع فقط. تعرض البطاقة في رأسها طرق التقييم المعتمدة ومجموع أوزانها. لا تظهر طرق التقييم غير المنطبقة داخل النوع.

| نوع العقار | الطرق المعتمدة في الواجهة الحالية |
|---|---|
| Apartment | Sales Comparison، Income، DCF |
| Villa | Sales Comparison، Income، Cost، DCF |
| Townhouse | Sales Comparison، Income، Cost، DCF |
| Office | Sales Comparison، Income، Cost، DCF |
| Retail / Shop | Sales Comparison، Income، Cost، DCF |
| Warehouse | Sales Comparison، Income، Cost |
| Land | Sales Comparison، Income |

إذا وجدت حقلًا لطريقة غير ظاهرة في نوع عقار معين، فهذا ليس نقصًا في اللوحة؛ بل يعني أن الطريقة غير معتمدة حاليًا لهذا النوع ولا ينبغي تعديل وزنها من هذه البطاقة.

## 6. Valuation Methods

يحتوي هذا القسم على **أوزان المناهج** المعتمدة لنوع العقار المحدد. تظهر القيم كنسب مئوية، مثل `55%`، بينما تحفظ داخليًا بصيغة عشرية مثل `0.55`.

### قاعدة مجموع الأوزان

يجب أن يساوي مجموع الأوزان المعتمدة لكل نوع عقار **100%** ضمن هامش التحقق المطبق في الخادم. الأوزان غير المعتمدة يجب أن تبقى صفرًا ولا تدخل في المجموع.

| المظهر | الإجراء |
|---|---|
| المجموع `100.0%` باللون الطبيعي | يمكن الحفظ من ناحية قاعدة الأوزان. راجع التغيير نفسه قبل الحفظ. |
| المجموع أقل أو أكبر من `100.0%` باللون الأحمر | الحفظ ممنوع حتى تصحح أوزان المناهج المعتمدة. |
| ظهور **Save blocked: total must equal 100%** | عدّل الأوزان حتى يصبح المجموع 100%، ثم راجع بقية التغييرات. |
| تغير وزن طريقة غير معتمدة | لا ينبغي أن يظهر حقلها؛ لا تضفها يدويًا إلى configuration. |

يجب تعديل الأوزان بطريقة متوازنة. مثال: إذا زاد وزن Sales Comparison في Apartment، يجب خفض وزن Income أو DCF بالمقدار المناسب حتى يبقى المجموع 100%.

## 7. Valuation Factors

يعرض هذا القسم المعاملات مجمعة حسب اسم الحقل الظاهر للمستخدم في واجهة التقييم، بدل عرضها كقائمة تقنية غير منظمة. كل بطاقة حقل تحتوي فقط على المعاملات المرتبطة بذلك الحقل، وقد تعرض أكثر من مجموعة عندما يستخدم الحقل أكثر من منهج.

| بطاقة الحقل | أمثلة على ما قد تحتويه |
|---|---|
| **Total Area (sqm)** | Max Price Per Sqm ومعاملات المساحة في Cost Approach. |
| **Bedrooms** | No Bedroom Multiplier. |
| **Features & Amenities** | Feature Bonus Per Sqm. |
| **Year Built** | Age Depreciation وMinimum Age Multiplier ومعاملات الاستهلاك في Cost. |
| **Condition** | معاملات Condition لكل من Sales Comparison وCost عند انطباقهما. |
| **Finish Quality** | معاملات مستويات التشطيب. |
| **View Type** | معاملات الإطلالات وحدود View multiplier. |
| **Floor Level** | معاملات فئات الطوابق. |
| **Street Position** | معاملات Main وCorner وSecondary وQuiet. |
| **Building Condition** | معاملات حالات المبنى. |
| **Furnished Status** | معاملات Furnished وSemi-Furnished وUnfurnished. |
| **Annual Rent (AED)** | Vacancy Rate Percent وCap Rate Percent. |
| **Annual Expenses (AED)** | Expense Rate. |

وجود المعامل داخل بطاقة الحقل يعني أنه مرتبط بهذا المسار، لكنه لا يعني أن المستخدم سيُدخل قيمته دائمًا أو أن المسار سيعمل إذا كانت أدلة السوق أو المدخلات الأساسية ناقصة.

## 8. Advanced Calibration

يحتوي **Advanced Calibration** على معاملات إضافية لا ترتبط مباشرة بحقل واحد ظاهر للمستخدم، ومن أهمها معاملات **DCF** مثل:

| المجموعة | أمثلة |
|---|---|
| DCF projection | Years، Rent Growth Rate، Value Growth Rate، Net Operating Income Rate. |
| DCF terminal and discount | Terminal Value Rate، Discount Rate. |
| DCF fallback | Negative NPV Fallback، Fallback Cap Rate. |
| Additional method controls | معاملات داخلية أخرى مرتبطة بمنهج قابل للتطبيق. |

لا تغيّر هذه القيم لمجرد تحسين رقم واحد. يجب أن يسبق التغيير اختبار محلي معزول، ومقارنة على أكثر من نوع عقار وفترة أو عينة، وتوثيق للأثر المتوقع وغير المتوقع. إذا لم يكن سبب المعامل واضحًا، اتركه كما هو واطلب مراجعة منهجية.

## 9. Experimental Shadow Controls

تظهر هذه المنطقة لبعض الأنواع التي تستخدم حقول v2.1 التجريبية، وتشمل:

| بطاقة الواجهة | وظيفتها الحالية |
|---|---|
| **Project / Building Name** | معامل Shadow للمشروع أو المبنى عند وجود دليل DLD كافٍ. |
| **BUA / Plot Area** | شرائح معامل Shadow لنسبة BUA إلى Plot Area. |
| **Last Renovation Year** | شرائح معامل Shadow لعمر آخر تجديد. |
| **Shadow Settings** | تفعيل Shadow، الحد الأدنى لأدلة المشروع، والحدود الدنيا والعليا للمعامل المركب. |

هذه المعاملات **لا تستبدل القيمة الرسمية** عندما يكون Shadow معطلًا، ولا يجوز تفعيلها في الإنتاج لمجرد التجربة. القيمة الافتراضية المحايدة هي `1.00×`، والإعداد الافتراضي للتفعيل هو التعطيل.

اسم المشروع المكتوب يدويًا لا يصبح موثقًا تلقائيًا. لا تضف Project multiplier إلا بعد وجود اقتراح DLD موثق وحد أدنى من الأدلة وفق الإعداد الحالي. لا تعِد تسمية Total Area أو `area` إلى BUA أو Plot Area، ولا تولّد قيمًا اصطناعية لحقول لا يوفرها المصدر.

## 10. الإعدادات المشتركة Location & Facilities

في نهاية اللوحة توجد بطاقة **Location & Facilities** لإعدادات GIS المشتركة، مثل أوزان أنواع المرافق، دائرة البحث، سقف الأثر، decay، والحدود الدنيا والعليا لمضاعف القرب.

هذه القيم تؤثر في مسار المرافق والموقع، وقد تعتمد على خدمة GIS خارجية. لا تغيّرها بناءً على خريطة واحدة أو فشل مؤقت في جلب المرافق. أي تعديل يحتاج إلى اختبار تغطية وتأثير، مع التأكد من عدم إنشاء أثر مصطنع عند غياب بيانات GIS.

## 11. سير العمل الآمن لتعديل قيمة

ابدأ بتسجيل الإصدار النشط وسبب التغيير، ثم حدّد نوع العقار والحقل أو المعامل الذي تريد مراجعته. اختبر التغيير أولًا في بيئة محلية معزولة بذاكرة مؤقتة، من دون Admin token أو طلب POST أو تعديل artifacts الرسمية. غيّر قيمة واحدة أو مجموعة مترابطة بوضوح، واحتفظ بنتيجة baseline والنتيجة المعدلة.

بعد نجاح الاختبار، افتح بطاقة نوع العقار الصحيحة في اللوحة الحية، وعدّل الحقل المقصود فقط. راقب مجموع الأوزان، ثم راجع **Save directly**. لا تستخدم **Save and activate** إلا عندما تكون القيم مفهومة، ومجموع كل نوع عقار صحيحًا، والتغيير موثقًا.

بعد الحفظ، سجّل `configId` الجديد وتاريخ التفعيل. نفّذ تقييمًا جديدًا بعينة اختبار معروفة وتأكد من أن التقييم الجديد يستخدم الإصدار المقصود. لا تتوقع أن تتغير النتائج التاريخية تلقائيًا؛ فهي تحتفظ بهوية المعايرة التي استخدمتها وقت إنشائها.

## 12. الحفظ وإعادة التحميل

زر **Save and activate** يحفظ configuration كاملة ويجعلها نشطة فورًا للتقييمات الجديدة. لا توجد في اللوحة الحالية خطوة منفصلة باسم Preview أو Draft. يجب اعتبار الضغط على هذا الزر إجراءً إنتاجيًا.

زر **Reload active** يحمّل الإصدار النشط من الخادم. استخدمه عندما تريد التخلص من تعديلات غير محفوظة أو التأكد من أن الصفحة تعرض آخر إصدار. انتبه إلى أن إعادة التحميل تهمل التعديلات المحلية غير المحفوظة.

إذا اكتشفت بعد الحفظ أن القيمة غير مناسبة، لا تعدّل history يدويًا ولا تحذف سجلًا. أنشئ إصدارًا جديدًا مصححًا بعد اختبار ومراجعة، ثم وثّق سبب التصحيح والإصدارين المتأثرين.

## 13. Version history

يعرض **Version history** أحدث الإصدارات المحفوظة مع `configId` والتاريخ والمسؤول. استخدمه للتدقيق ومعرفة متى تغيّرت المعايرة، ولا تعتبر ظهوره بديلًا عن خطة rollback أو مراجعة تغيير رسمية.

يجب أن يتضمن سجل العمل الداخلي لكل تغيير: الإصدار السابق، الإصدار الجديد، نوع العقار، الحقل أو المعامل، القيمة السابقة، القيمة الجديدة، سبب التغيير، نتائج الاختبار، ونطاق التفعيل. لا تضع Admin token في هذا السجل.

## 14. التعامل مع الأخطاء

| الحالة | ما يجب فعله |
|---|---|
| **Enter the administrator token first.** | أدخل token في الحقل المخصص فقط، وتأكد من عدم وجود مسافات زائدة. |
| **Request failed** أو **Not connected** | لا تعاود الحفظ. تحقق من الاتصال والصلاحية، ثم أعد التحميل عند الحاجة. |
| **Save blocked: total must equal 100%** | راجع أوزان الطرق المعتمدة لكل نوع وأعد مجموعها إلى 100%. |
| اختفاء حقل أو منهج | تحقق من نوع العقار؛ قد يكون الحقل أو المنهج غير منطبق حاليًا. |
| ظهور قيمة غير مفهومة | أوقف التعديل، أعد تحميل الإصدار النشط، وراجع مصدر المعامل قبل أي حفظ. |
| تغير نتيجة جديدة بعد الحفظ | تحقق من `configId` الجديد، ولا تخلط بين التقييمات الجديدة والنتائج التاريخية. |

## 15. قائمة تحقق قبل Save and activate

| السؤال | يجب أن تكون الإجابة |
|---|---|
| هل التغيير مفهوم ومحدد؟ | نعم، مع سبب مكتوب. |
| هل تم اختبار التغيير محليًا أو في تجربة معزولة؟ | نعم، دون token أو POST إنتاجي. |
| هل مجموع الأوزان 100% لكل نوع عقار؟ | نعم، ويظهر باللون الطبيعي. |
| هل بقيت الطرق غير المنطبقة خارج التعديل؟ | نعم. |
| هل تم الحفاظ على القيم والـartifacts الرسمية غير المتعلقة بالتغيير؟ | نعم. |
| هل عُرف أثر التغيير على التقييمات الجديدة فقط؟ | نعم. |
| هل سُجل الإصدار الجديد بعد الحفظ؟ | يجب تسجيله فورًا. |

## 16. حدود المسؤولية

مدير المعايرة لا ينبغي أن يرفع أو يخفض قيمة العقار يدويًا بهدف مطابقة نتيجة مرغوبة. وظيفة اللوحة هي إدارة معاملات موثقة وقابلة للاختبار، لا تعديل النتائج الفردية. Accuracy وDLD artifacts الرسمية محمية، ولا يجوز تغييرها يدويًا لتبرير معامل جديد.

تظل MIAYAAR منصة تجريبية ومحدودة الاستخدام. أي تغيير منهجي في طرق التقييم أو fallback أو تفعيل Shadow يحتاج إلى قرار مستقل، تجربة مقارنة، وموافقة واضحة قبل اعتماده.
