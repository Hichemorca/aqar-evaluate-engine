## Observation submit behavior

A local browser test stubbed the POST request and confirmed that checking the opt-in sends `POST /api/valuation-observation`, includes `consent.analytics: true`, and displays the success message. The payload did not contain identity keys.

A second test with consent unchecked made zero fetch calls, confirming that recording is opt-in. It exposed a small UX issue: an old success message remained visible after consent was unchecked. The recording function should clear `observationStatus` when consent is not selected so stale success text cannot be misread as a new submission.

## Reload verification

The page was reloaded after the stale-message fix. The opt-in checkbox remains unchecked by default, the Calculate Valuation button remains enabled, and the endpoint remains available through the existing `/api/*` redirect to Netlify Functions.
